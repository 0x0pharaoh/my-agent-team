# my-team v0.4 — Control plane (approved plan, 2026-10-08)

## Context

**Where things stand:**
- my-team is a loopback FastAPI + SQLite daemon with a React/Vite/Tailwind dashboard.
- v0.3 (branch `v0.3`, PR #2 open, 6 server CI jobs red) added headless agent runs, worktrees, budgets, pipelines, lead routing, must-reply runs and Graphify.
- The UI is still one 1,280-line `ui/src/App.tsx`:
  - indigo/zinc styling;
  - tab state with no URLs;
  - no drag and drop;
  - a full refetch on every SSE frame.

**What you want:** a human + AI engineering control plane.
- Board with persisted drag and drop, and a ticket drawer.
- Agent roster, workspace and live run output.
- Inbox with chat and an Orchestrator.
- Memory, Approvals, Notifications, Dashboard, Analytics, Automations and Search.
- An optional Agent Floor, plus Repo and Docs upgrades.
- The pink/cream editorial design from your mockups, with URL routing.

Munder Difflin gives **product behaviour only**. We copy no code, assets or branding.

**The work:** 66 tickets in your real my-team (project MT), all for OpenCode, in approval-gated slices. The work builds on the existing daemon and op registry; nothing is rewritten.

This plan went through 3 adversarial read-only reviews against the v0.3 code: codebase fit, security, and spec coverage. All 3 blockers and every major finding are folded in below.

## Cross-cutting rules

These rules apply to every ticket. They come from the reviews.

### Identity
- Humans are `Actor('human', user_id, role)`, with role re-read from `human_sessions JOIN users WHERE disabled_ms IS NULL` on **every** request.
- Every `!= HUMAN` check becomes `not actor.is_human` or `require_owner(actor)`. The sites are `daemon/app.py:182,195,252,261,271,289,297,379`; the purge actor at `app.py:279` changes too.
- `Op` gets `owner_only: bool`, checked in `project_call` and `registry_call`.
- The raw routes `memory_purge`, `db_backups` and `db_restore` call `require_owner`.

### Registry access
- Project ops cannot read the registry.
- `project_call` therefore loads a **registry snapshot** (users: id, handle, name, role, presence) into `Ctx` before `db.write`.
- Cross-project views (unread count, search, analytics by project) use one async daemon route that fans out over `state.project_db(pid)`. They are **not** registry ops.

### Messages
- `_me` returns `('human', actor.id)` for humans and `('system', 'system')` for SYSTEM.
- A human recipient is `('human','*')` (all humans) or `('human', <user_id>)`. Per-user read state goes in `human_reads(message_id, user_id, read_ms)`.
- Legacy `('human','human')` migrates to `'*'`, and its read state goes to user `human`.
- `docs.py:188` targets `'*'`.
- `_serialize` adds `sender_id`.
- **Human↔human DMs are private** in every read path: recent, channels, thread, search, activity, SSE payload. Agent↔agent and agent↔human threads stay visible to all humans.

### Notifications
- Notifications are **derived at read time** from events. A pure `notify` mapper turns an event into an audience: `*`, a user, or none.
- Storage is one table, `notification_reads(event_id, user_id)`, plus a per-user `read_all_ms` watermark.
- Caps are keyed by (project, agent_type): at most 20 human-targeted notifications per hour, coalesced.

### Runs
- The tick launches at most `max_parallel_runs` minus the running count; this covers manual runs too.
- `run_start` refuses tickets that have open blockers.
- Run output (`run_log`, transcript items) passes through `redact`. The run is looked up in the project from the path.
- `edit_check` joins `NO_NOTICES`, so hooks stop eating STOP and answer notices.

### Migrations
- **Engine fix:** `migrate` runs `foreign_key_check` **inside** the open transaction, then commits or rolls back.
- **Table rebuild recipe** (tickets, ticket_links, memories):
  1. Create `X_new`.
  2. Copy the rows, listing `rowid` explicitly.
  3. Drop `X`.
  4. Rename `X_new` to `X`.
  5. Recreate every index and trigger with unquoted names.
  6. For memories, run `INSERT INTO memories_fts(memories_fts) VALUES('rebuild')`.
- The rebuild carries every ALTER-added column (`paths`, `sprint_id`, `max_tokens`, `max_minutes`, `workflow`, `step`).
- Each rebuild is tested on a v0.3-shaped DB. Before release it is dry-run on a **copy** of your real DB.

### Process safety
- The daemon spawns with `cwd = private_data_dir()` and `NoDefaultCurrentDirectoryInExePath=1`. git and gh are resolved once at startup.
- This closes an existing hole: on Windows a repo-planted `git.exe` or `gh.bat` would otherwise run as the owner.

### Gates
Each slice ends at a gate:
- pytest, ruff, `pnpm lint`, `pnpm build`, vitest and Playwright pass, and **all 8 CI jobs** are green;
- every new view has loading, empty, error and offline states, plus a success toast;
- screenshots at 1440 px and 375 px.

Live agent runs are evidence only, never gates; the gates use the deterministic `fake_agent` tests.

## Risks
- **Scope:** 66 tickets. The gates let you cut or reorder. C12 and C9-3 are the cheapest to drop.
- **Members on the same machine:** a member can execute code as the owner's OS user through unsandboxed agents. Owner-only starts reduce the risk. SECURITY says plainly that roles guard against mistakes, not a malicious member.
- **Table rebuilds:** recipe + tests + a dry run on a copy of your real DB.
- **Token spend:** the Orchestrator and automations spend tokens. Controls: budgets, the breaker, `auto_run`, bundles, rate limits.
- **Unverified driver shapes:** Codex and Hermes run output is unverified, so the transcript degrades to raw lines.
